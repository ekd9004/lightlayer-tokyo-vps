## Premium 和 Global 两条线路，路由差在哪

**Premium 优化线路**三网去程都是直连。电信从广州出口走电信骨干网到东京；联通从上海出口走 AS4837 直连；移动从上海出口走 CMI 骨干网直连。全国三网 Ping 平均 65ms，电信 65ms、联通 64ms、移动 66ms，三家几乎持平。

回程实测里，北京、上海、广州、成都的三网节点都能识别到电信 CTGNET 精品线路加 163 普通线路的组合。广州电信回程 9.74ms 到东京本地，约 50ms 到广州，54ms 到深圳；广州联通经 CTGNET 转 AS4134 再入联通 AS17516/AS17623，约 51 到 62ms。移动的回程稍复杂，部分节点跑到 108 到 153ms。

**Global 国际 BGP 线路**的走法不一样。电信去程走 NTT 直连东京，回程直连；联通去程同样走 NTT，回程也直连；移动去程要绕到美国圣何塞再回日本，这一段延迟明显更高，回程大部分节点是直连的。这条线的国内平均延迟测出来 59ms。

带宽方面，三条线在这台 100M 的机器上都能跑满，上下对等 100M，没有偏科。对日本机房来说，这个流量给得算大方。

## 三个延迟数字，分别对应哪种测法

搜 lightlayer 东京的时候会看到 65ms、97ms、59ms 三个数，容易搞混。它们不是同一件事：

**97ms** 是测评者在自己本地网络 Ping 的平均值，测的是单条家宽到东京的往返，基本没有丢包。这个数字受测评者所在地影响很大，你本地测出来可能差不少。

**65ms** 是全国三网 Ping 的平均值，同样是 Premium 线路。这个更接近"国内用户整体感受"，三网分别 65 / 64 / 66ms，分布很均匀。

还有一种测法值得看：Premium 线路在未开 BBR 的情况下，日本东京节点上传 31.59 / 下载 30.12 Mbps，联通上海 5G 延迟 33.16ms，电信浙江 52.23 和 72.30ms，移动杭州 5G 36.13ms，各地上下行基本跑满 30M 标称带宽，丢包率 0.0%。这说明线路的带宽是实标的，不是超售到跑不动的数字。

## 硬件实测：CPU 和顺序读写不错，4K 随机是短板

Premium 线路那台 1 核 1G 的机器，宿主机是 AMD EPYC 7702，KVM 虚拟化，实测 CPU 频率 1996MHz。sysbench 单核 1640 Scores，内存单线程读 43961 MB/s、写 19509 MB/s。

磁盘的数字要分开看。1GB-1M 块读写都是 698 MB/s，fio 512k 读 450.17 MB/s、写 474.09 MB/s，另一篇 BGP 线路的测评也测到硬盘平均读写 650MB/s。大块顺序读写对一台低价 VPS 来说相当好。

问题在 4K 小块：只有 3.4 MB/s，约 826 IOPS。这个数字意味着频繁的小文件随机读写会很吃力。跑 MySQL 且数据量稍大、跑大量小文件读写的应用（比如某些 CMS 的缓存目录、Git 仓库、邮件队列），会明显感觉到卡。静态站、反向代理、轻量 API、爬虫出口这类以顺序读写和网络为主的应用，不受影响。

另一个细节：系统默认分配了 8GB swap。虚拟内存是从硬盘划的，所以 50GB 的盘实际读出只有 42GB 可用。测评者的评价是"有点浪费"，2GB 就够了。装完系统第一件事可以看看 swap 要不要调小。

## IP 属性与流媒体解锁：能用什么，不能用什么

这部分争议最大，两篇测评测出来的结果完全不同，都必须说清楚。

**Premium 线路那台的 IP**（AS984 OCTOPUS WEB SOLUTION，位置东京杉并区）：Netflix 可解锁日本区，Amazon Prime Video 日本区，YouTube Premium 美国区、CDN 落在东京，ChatGPT 可用，Google Gemini 可用（美国区）。不可用的有 Claude、Disney+（IP 被 Disney+ 封禁）、Reddit。TikTok 区域显示菲律宾。

IP 质量检测里，是否代理、是否 VPN、是否 Tor 全部为 No，威胁级别 low，313 项 DNS 黑名单检查中有 9 项列入黑名单，另有 19 项标记为 Other。**Google 搜索可行性显示 NO**，这一点值得单独拎出来：如果你打算用这台机器做谷歌搜索相关的业务、SEO 工具、或者需要 Google 判定为正常流量的场景，先自己验证 IP 再付款。

**Global 线路那台的 IP** 更特殊。脚本判定为德国原生 IP，能解锁德国 TikTok、德国 Netflix 和部分欧洲流媒体。ip 库两个 type 值都是 isp，等于日本双 ISP，但 ping0.cc 判定为机房 IP 且 IP 风险高，是否家宽、纯净度如何，各家数据库说法不一致。官方这个套餐从没宣传过是 ISP IP。

想要干净原生 IP 的，别指望随机开通的机器一定合心意。IP 段是分配制的，同一套餐不同 IP 的表现可能不同，下单前把自己的用途跟客服讲清楚，比事后换 IP 省事。
